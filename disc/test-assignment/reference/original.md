# Оригинал: DISC-тест Stratoplan

Источник (снято 2026-11-14):

- страница теста: `https://stratoplan-school.com/disc/`
- скрипт теста: `https://stratoplan-school.com/disc/js/disc_patched.js?v=0.0.0.6`
- страница результата: `https://stratoplan-school.com/disc/result/` (дешифровка
  токена — инлайн-скрипт)

## Поток пользователя

1. **Лендинг**: h1 «Бесплатный тест DISC для руководителей», описание,
   кнопка «Пройти тест» — открывает модалку-визард.
2. **Модалка «Тестирование DISC»**: подзаголовок «Помните — чем честнее вы
   с тестом, тем точнее результаты!», инструкция «Разместите блоки в порядке
   от наиболее похожего на вас до наименее похожего».
3. **8 шагов** (табы «Первый»…«Восьмой»), на каждом шаге 3 вопроса
   (сетка `.disc-grid3`) — всего **24 вопроса**.
4. **Вопрос** = карточка: сверху подпись «Я наиболее», ниже список из
   4 прилагательных, снизу подпись «Я наименее». Пользователь перетаскиванием
   ранжирует прилагательные: самое похожее — вверх, наименее похожее — вниз.
   Drag&drop — SortableJS 1.15.2 с CDN (fallback: HTML5 DnD); на тач-устройствах
   перетаскивание только за «ручку» (иконка-точечки, инлайн SVG).
5. **Навигация**: «Назад» (disabled на шаге 1), «Далее», на последнем шаге —
   «Завершить тест». Прогресс-бар: `(шаг+1)/8`.
6. **Завершение**: сбор ответов → подсчёт баллов → упаковка в токен →
   модалка сбора email (formdesigner в iframe, `#apruve`) → после успешной
   отправки формы редирект на страницу результата с токеном в query.

## Подсчёт баллов (из `disc_patched.js`, функция `score`)

- По каждому вопросу: прилагательное на позиции 1 (верх, `pos === 0`) —
  «major» (+1 своему типу), на позиции 4 (низ, `pos === 3`) — «minor» (−1).
  Порядок двух средних позиций на баллы не влияет.
- Балл типа = `(число major типа) − (число minor типа)`.
- В каждом вопросе ровно по одному прилагательному каждого типа (d/i/s/c) →
  по тесту 24 вхождения каждого типа; балл типа ∈ [−24, +24]; сумма баллов
  четырёх типов всегда 0 (каждый вопрос даёт ровно один +1 и один −1).

## Токен результата

- payload: `{"v":1, "ts":<ms>, "score":{"d":…,"i":…,"s":…,"c":…}}`
- шифрование AES-GCM (WebCrypto): ключ = SHA-256 от строки
  `disc@v1::client-only`, IV 12 байт случайный; токен = base64url(IV || шифртекст);
- токен кладётся в `sessionStorage` (`disc_result_token_v1`);
- страница результата: `https://stratoplan-school.com/disc/result/?<token>`
  расшифровывает токен тем же секретом и показывает строку `D:x, I:y, S:z, C:w`.

## Страница результата

- заголовок «Ваш DISC-профиль:» + строка баллов (по умолчанию при битом
  токене — `D:0, I:0, S:0, C:0`);
- **индивидуальной интерпретации нет**: ссылка «По данной ссылке вы можете
  ознакомиться с общей расшифровкой результатов» (внешняя страница) и
  дисклеймер: «Обратите внимание: мы не даём расшифровку ваших индивидуальных
  результатов. Вместо этого мы помогаем вам научиться использовать этот
  инструмент для самотестирования, а также для дальнейшей работы с вашими
  командами, сотрудниками и коллегами»;
- кнопка «Поделиться результатами теста» (копирование ссылки с токеном),
  видео «как интерпретировать результаты теста DISC», блоки-подарки
  (курс, телеграм), футер.

## Данные вопросов

- 24 вопроса — в `questions.json` (эталон): id, шаг (0–7), позиция в шаге,
  исходный `list_id` из DOM, 4 элемента `{type, text}` в исходном порядке
  DOM (это стартовый порядок списка до перетаскивания).
- type — служебный атрибут `data-type` из оригинала, пользователю не
  показывается.

## Особенности оригинала (воспроизводить как есть)

1. В вопросе 1 слово «Экспресcивный» содержит **латинскую «c»** внутри —
   сохранить посимвольно.
2. Прилагательные повторяются между вопросами, иногда с разными типами:
   Волевой (d, d), Осторожный (s, c), Сдержанный (s, c, c), Настойчивый
   (d, d, i), Убедительный (i, i, i), Точный (c, c), Уравновешенный (i, s),
   Решительный (d, d), Требовательный (d, c).
3. Часть назначений типов выглядит ошибочным с точки зрения теории DISC
   (например «Энтузиаст» → c, «Исполнитель инструкций» → d, «Шутливый» → d,
   «Безропотный» → c, «Смиренный» → c). Эталоном считаем data-type оригинала
   как есть — задание на воспроизведение, а не на исправление.
