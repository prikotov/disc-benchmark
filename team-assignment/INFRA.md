# Инфраструктура: что нужно от владельца

Чек-лист вопросов владельцу (Дмитрию) перед первым командным прогоном.
Ответы фиксируются здесь (без секретов) и в `.env.local` (только пути
к файлам с ключами, файлы вне репозитория). Скрипты и промпты содержат
только имена переменных, не значения.

## 1. LLM API для интерпретации результата

- [ ] провайдер и base URL (OpenAI-совместимый?);
- [ ] модель для интерпретации (качество русского текста важно);
- [ ] ключ → файл вне репо, путь в `DISC_LLM_KEY_FILE`;
- [ ] лимиты/стоимость: платные вызовы журналируются в `reports/spend.csv`
      (интерпретации на проде — расход владельца, не бенчмарка; тестовые
      вызовы команды во время прогона — учитывать).

Переменные: `DISC_LLM_BASE_URL`, `DISC_LLM_MODEL`, `DISC_LLM_KEY_FILE`.

## 2. Почта (SMTP)

- [ ] хост/порт/шифрование/логин/пароль → Symfony Mailer DSN в файле
      вне репо (`DISC_SMTP_DSN_FILE`; раннер подставляет значение
      в `DISC_SMTP_DSN` при запуске);
- [ ] разрешённый отправитель (from);
- [ ] **контрольный ящик тестировщика** (`DISC_TEST_MAILBOX`) — куда
      tester шлёт проверочные письма и как к нему доступ (IMAP/веб).

## 3. Деплой на ai-aid.pro

- [ ] SSH-доступ: хост, пользователь, ключ → файл вне репо
      (`DISC_DEPLOY_HOST`, `DISC_DEPLOY_USER`, `DISC_DEPLOY_KEY_FILE`);
- [ ] корневой путь веб-приложений (`DISC_DEPLOY_ROOT`) и как раздаётся
      подпуть `/disc-v-<имя версии>/` (nginx alias / отдельный location /
      нужно ли править общий конфиг — если да, кто это делает);
- [ ] PHP на сервере: версия, расширения (curl/mbstring/xml и т.п.),
      PHP-FPM или модуль; composer на сервере есть или vendor деплоится
      собранным;
- [ ] права: может ли деплой-пользователь создавать каталоги и писать
      в свой путь; есть ли БД (или SQLite-файл в своём пути);
- [ ] SSL на домене уже настроен?

## 4. Имя версии

- [ ] формат и кто присваивает: предложение — владелец утверждает имя
      на каждый прогон (например `disc-v-alpha-01`), оно фиксируется
      в `run.json` до старта; коллизии путей исключены.

## 5. Границы безопасности

- деплой-доступ ограничен путём `/disc-v-*/` (подтвердить или настроить);
- SMTP-доступ не позволяет слать что угодно кому угодно (лимиты/relay);
- LLM-ключ с лимитом расхода.

## Контракт окружения (итог)

| Переменная | Значение | Где хранится |
|---|---|---|
| `DISC_LLM_BASE_URL` | адрес LLM API | `.env.local` |
| `DISC_LLM_MODEL` | модель интерпретации | `.env.local` |
| `DISC_LLM_KEY_FILE` | путь к файлу ключа | `.env.local` (ключ вне репо) |
| `DISC_SMTP_DSN` | Mailer DSN | файл вне репо (`DISC_SMTP_DSN_FILE` в `.env.local`) |
| `DISC_DEPLOY_HOST` | хост прода | `.env.local` |
| `DISC_DEPLOY_USER` | SSH-пользователь | `.env.local` |
| `DISC_DEPLOY_KEY_FILE` | путь к SSH-ключу | `.env.local` (ключ вне репо) |
| `DISC_DEPLOY_ROOT` | корень веб-приложений | `.env.local` |
| `DISC_TEST_MAILBOX` | контрольный ящик tester | `.env.local` |
