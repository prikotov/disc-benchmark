# Инфраструктура: что нужно от владельца

Чек-лист вопросов владельцу (Дмитрию) перед первым командным прогоном.
Ответы фиксируются здесь (без секретов) и в `.env.local` (только пути
к файлам с ключами, файлы вне репозитория). Скрипты и промпты содержат
только имена переменных, не значения.

## 3. Деплой на ai-aid.pro — схема проверена на aserv (2026-11-28)

Факты сервера (осмотр): RHEL-семейство, nginx 1.20.1, php-fpm 8.4.27
(пулы `www`/`apache`, `wwwtask`/`wwwtask`), прод — `task.ai-aid.pro`
(Symfony, пул wwwtask); `ai-aid.pro` 301-редиректит с сохранением пути,
SSL (LE) работает. `rrsync` не установлен — поставить в
`/usr/local/bin/rrsync` (perl на сервере есть). Composer на сервере
не нужен — деплоим артефакт с vendor.

### Проверенная схема (все пункты прогнаны на тестовом стенде aserv)

- Каталог версий: `/srv/disc/disc-v-<имя>/` — приложение в docroot-стиле
  (`index.php` в корне версии, vendor/ рядом); новая версия = новый
  каталог, **nginx и php-fpm не трогаются никогда** (без reload).
- Один generic nginx-блок в `task.ai-aid.pro.conf` (см.
  `infra/aserv.md`): `location ^~ /disc-v-` + вложенный regex php-локейшн
  с захватом версии. **Паттерн `alias` внутри regex-location не работает**
  (проверено: `fastcgi request length mismatch`) — используется `root`.
- Изоляция per-version: `fastcgi_param PHP_VALUE "open_basedir=/srv/disc/disc-v-$ver"`
  — **проверено**: `/etc/passwd` и продовое приложение task из disc-кода
  BLOCKED, свои файлы читаются. Дополнительно: `upload_tmp_dir` внутри
  версии (деплой создаёт `var/tmp`), секреты через `fastcgi_param`
  `DISC_*` — доставка env **проверена**.
- Канал деплоя: один юзер `disc` (владелец `/srv/disc`), SSH-ключ с
  forced command `rrsync -wo /srv/disc` + `from="<IP владельца>"` +
  `no-port-forwarding,no-agent-forwarding,no-X11-forwarding` — shell нет,
  канал только заливка (чтение запрещено, в т.ч. собственных файлов —
  код и так есть у команды локально).
- Секреты продакшена (SMTP DSN, LLM-ключ) живут в nginx-конфе
  (`fastcgi_param`), до агентов не доезжают: код читает `$_SERVER`.
- Ключ SSH: файл вне репо (`DISC_DEPLOY_KEY_FILE`), в песочницу не
  попадает — раннер держит `ssh-agent` на хосте и пробрасывает сокет
  (`SSH_AUTH_SOCK` через `SANDBOX_ENV_PREFIX`); агент пользуется ключом,
  но прочитать его не может.

### Что делает владелец один раз (по шагам — `infra/aserv.md`)

1. Создать юзера `disc` + пул `wwwdisc` (user disc,
   `/run/php-fpm/wwwdisc.sock`, `php_admin_value[open_basedir]=/srv/disc`
   вторым слоем защиты).
2. Вставить generic-блок в `task.ai-aid.pro.conf` + секреты в
   `fastcgi_param` (значения не в git).
3. Установить `rrsync`, создать ключ, вписать `from="<IP>"`.

На прогон — **ничего**: каталог версии rsync создаёт сам.

- [x] PHP 8.4 на сервере (Symfony 8.1 совместим), расширения на месте;
- [x] SSL настроен, путь `/disc-v-*` раздаётся generic-блоком без правок;
- [x] деплой-юзер создаёт каталоги и пишет в свой путь (rrsync -wo);
- [x] БД не нужна (SQLite в своём пути);
- [x] изоляция версий: open_basedir per-version — проверено;
- [ ] выполнить шаги провижининга из `infra/aserv.md`.

Переменные: `DISC_DEPLOY_HOST` (task.ai-aid.pro / aserv),
`DISC_DEPLOY_USER` (disc), `DISC_DEPLOY_ROOT` (/srv/disc),
`DISC_DEPLOY_KEY_FILE` (файл ключа вне репо → ssh-agent раннера).

## 4. Имя версии

- [x] формула детерминирована: **`disc-v-<слаг серии>-r<NN>`**
      (пример: `disc-v-team-inkling-r01`); имя = имя каталога,
      вычисляется раннером из слага композиции и номера прогона и
      фиксируется в `run.json`. Коллизии исключены; владелец участвует
      только в утверждении слага композиции (как и было) — на каждый
      прогон ничего присваивать не нужно.

## 5. Границы безопасности

- канал деплоя: `rrsync -wo` + forced command — технически без shell и
  без чтения (см. §3);
- поведение (слова, проверяется судьёй по трейсам): devops работает
  только в своём `/disc-v-<имя>/`; другие `/disc-v-*` не открывать и не
  сканировать; имена чужих версий агентам не сообщаются — нет указания,
  нет и соблазна; сетевой egress песочницы — мониторится, нарушения
  превращаются в метрику;
- SMTP-доступ не позволяет слать что угодно кому угодно (лимиты/relay);
- LLM-ключ продакшена с лимитом расхода, доставка через
  `fastcgi_param` — агентам не выдаётся.
