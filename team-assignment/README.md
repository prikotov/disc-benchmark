# team-assignment: DISC-продукт с нуля, LLM-команда

Второе тестовое задание workspace (рядом с `test-assignment/` — копией
страницы). Здесь команда LLM-агентов строит **полноценный продукт**:
анкету DISC на данных Stratoplan, но как веб-приложение — Symfony
(PHP-бэкенд), индивидуальная интерпретация результата через LLM,
отправка результата на почту, деплой на продакшен
`https://ai-aid.pro/disc-v-<имя версии>/`, мобильник и десктоп.

Отличия от одиночного задания:

- **spec-driven**: процесс описан в задании (как делать анкету, как
  считать, как проводить тестирование, как предоставлять результат),
  данные анкеты приложены (`reference/questions.json`); внешний вид
  и архитектура — за командой;
- **команда**: роли по Белбину, поведение сконфигурировано DISC-профилями
  (условие A; нейтральные описания для A/B-серии — позже); роли запускаются
  сабагентами pi (расширение `subagent`), тимлид-оркестратор управляет;
- **критерий продукта**: разработан, протестирован, задеплоен на прод
  и работает там.

## Структура

| Путь | Что лежит |
|---|---|
| `TASK.md` | канонический текст задания (получает команда) |
| `reference/questions.json` | исправленный эталон анкеты — приложение к заданию (база Stratoplan + правки по книге Эриксона) |
| `reference/questions.stratoplan.json` | дословный оригинал Stratoplan (провенанс) |
| `reference/corrections.md` | таблица правок: аудит книги, спорные позиции по шкале самооценки, ребалансировка |
| `reference/README.md` | провенанс данных и правила для судей |
| `prompts/prompt.json` | задание для прогона (версионируется; v1 — TASK + данные) |
| `roles/` | 7 карточек ролей (Белбин × DISC) в формате pi-агентов |
| `team.json` | состав команды: роль → модель → уровень (утверждает владелец) |
| `ORCHESTRATION.md` | как устроен прогон: раннер, сабагенты, среда обмена, правила |
| `rubrics/scorecard.md` | рубрика (4 оси 0–4), план машинных проверок, поведенческие метрики |
| `INFRA.md` | чек-лист инфраструктуры: LLM-ключ, SMTP, деплой (вопросы владельцу) |

Раннер (`runner.py`), чекер (`check.py`), судья (`judge.py`) — будут
написаны здесь по образцу `test-assignment/`. Результаты в этой папке
не живут: командные прогоны — `runs/<слаг>/run-XX/` внутри этой папки
(см. `ORCHESTRATION.md`), кросс-командные своды — `reports/`.

## Статус

Методология готова (задание, роли, оркестрация, рубрика, исправленный
эталон). До первого прогона нужно: утверждение владельцем таблицы правок
(`reference/corrections.md`), ответы по `INFRA.md` (LLM API, SMTP, деплой,
контрольный ящик, имя версии), утверждение состава `team.json`, раннер.
