# Тестовое задание: анкета DISC — полноценное веб-приложение

Постройте с нуля веб-приложение для прохождения теста личности DISC.
Это не статичная копия страницы, а продукт: PHP-бэкенд на Symfony,
индивидуальная интерпретация результата через LLM, отправка результата
на почту и деплой на продакшен.

Вы работаете командой: роли и зона ответственности каждого участника
выданы отдельно. Тимлид организует процесс и отвечает за продукт целиком.

## Анкета (данные — в приложении к заданию)

За основу взята анкета DISC школы менеджмента Stratoplan
(https://stratoplan-school.com/disc/). Данные приложены к заданию файлом
`questions.json`:

- **24 вопроса**, сгруппированные в **8 шагов по 3 вопроса**;
- в каждом вопросе **4 прилагательных**, у каждого — служебный тип
  `d` / `i` / `s` / `c` (пользователю типы не показываются);
- в каждом вопросе ровно по одному прилагательному каждого типа.

Используйте данные как есть: формулировки, типы, порядок вопросов
и группировку по шагам. Известные опечатки источника (например, латинская
«c» внутри слова «Экспресcивный» в вопросе 1) исправлять можно, но каждое
исправление зафиксируйте в журнале команды.

## Как проводить тестирование (поток пользователя)

1. **Стартовый экран**: заголовок, краткое описание теста, кнопка
   «Пройти тест».
2. **8 шагов**, на каждом 3 вопроса. В вопросе пользователь ранжирует
   4 прилагательных от «наиболее похожего на меня» (верх) до «наименее
   похожего» (низ). Механика ранжирования (перетаскивание, стрелки,
   клики — на ваше усмотрение) обязана работать и мышью, и тачем.
3. **Навигация**: «Назад» / «Далее», на последнем шаге — «Завершить»;
   индикатор прогресса по шагам. Возврат на предыдущие шаги с сохранением
   ответов.
4. **Сбор email**: после завершения теста пользователь вводит свой email
   для получения результата.
5. **Результат**: баллы по четырём шкалам D / I / S / C и индивидуальная
   интерпретация профиля; результат также отправляется на введённый email.

Внешний вид, вёрстка и оформление — на усмотрение команды. Язык
интерфейса — русский. Приложение должно одинаково хорошо работать
в мобильном и десктопном браузере (актуальные Chrome, Firefox, Safari).

## Как считать баллы

- В каждом вопросе прилагательное на **1-й позиции** («наиболее похожее»)
  даёт **+1** своему типу; на **4-й позиции** («наименее похожее») —
  **−1** своему типу. Две средние позиции не влияют на баллы.
- Балл шкалы = сумма по всем 24 вопросам. Балл каждой шкалы ∈ [−24; +24];
  сумма баллов четырёх шкал всегда равна 0.
- Подсчёт выполняется **на бэкенде**, не в браузере.

## Интерпретация результата (LLM)

- Бэкенд передаёт полученные баллы в LLM API и получает **индивидуальную
  интерпретацию** профиля на русском языке: описание профиля, сильные
  стороны, зоны роста, рекомендации по взаимодействию с людьми других
  типов. Интерпретация должна зависеть от фактических баллов: разные
  профили — разные тексты.
- Доступ к LLM API (адрес, модель, ключ) выдаётся через переменные
  окружения (см. «Окружение»). Ключи не хардкодить в коде и не коммитить.
- Если LLM недоступна, приложение всё равно показывает баллы и честно
  сообщает, что интерпретация временно недоступна (без выдуманного текста).

## Отправка результата на почту

- После завершения теста результат (баллы + интерпретация) отправляется
  на email, введённый пользователем. Отправка — через SMTP
  (Symfony Mailer), доступ выдаётся через окружение.
- Письмо содержит баллы по шкалам и текст интерпретации; оформление
  письма, отправитель и тема — на ваше усмотрение.

## Бэкенд и архитектура

- **PHP, Symfony** (актуальная стабильная версия). Структура проекта,
  способ хранения данных (БД или файлы), формат API — на усмотрение
  команды; приветствуется минимально достаточное решение.
- Данные анкеты хранятся на бэкенде; приём ответов, подсчёт баллов,
  обращение к LLM и отправка почты — серверная логика.
- Секреты (ключ LLM, SMTP, доступ к деплою) — только через переменные
  окружения, в репозиторий не попадают.

## Деплой (продакшен)

- Приложение размещается по адресу
  **https://ai-aid.pro/disc-v-<имя версии>/** — имя версии тимлид
  получает от владельца до старта и фиксирует в журнале.
- Доступ к деплою выдаётся через окружение. Менять можно **только свой
  путь** `/disc-v-<имя версии>/`; остальные части сайта трогать запрещено.
- **Продукт считается созданным**, когда он разработан, протестирован
  командой (отчёт тестировщика), задеплоен на указанный адрес и реально
  там работает: прохождение теста, подсчёт, интерпретация и отправка
  письма проверены на продакшене.

## Окружение (выдаётся владельцем, значений в задании нет)

| Переменная | Назначение |
|---|---|
| `DISC_LLM_BASE_URL` | адрес LLM API для интерпретации |
| `DISC_LLM_MODEL` | модель LLM для интерпретации |
| `DISC_LLM_KEY_FILE` | путь к файлу с ключом LLM API |
| `DISC_SMTP_DSN` | Symfony Mailer DSN для отправки почты |
| `DISC_DEPLOY_HOST` | хост продакшена |
| `DISC_DEPLOY_USER` | пользователь SSH для деплоя |
| `DISC_DEPLOY_KEY_FILE` | путь к файлу с SSH-ключом деплоя |
| `DISC_DEPLOY_ROOT` | корневой путь веб-приложений на сервере |
| `DISC_TEST_MAILBOX` | контрольный ящик тестировщика для проверки писем |

Значения переменных уже настроены в рабочем окружении команды. Не
печатайте значения секретов в логах, отчётах и письмах.

## Формат результата

- работающее приложение на продакшен-адресе;
- код проекта (Symfony-приложение) в рабочей директории команды;
- `team/journal.md` — журнал команды: решения, распределение задач,
  исправления данных, отчёты ролей;
- `team/test-report.md` — отчёт тестировщика (что проверено, результаты,
  дефекты);
- `team/final-report.md` — итоговый отчёт тимлида: что построено, как
  проверено, адрес продакшена, известные ограничения.
