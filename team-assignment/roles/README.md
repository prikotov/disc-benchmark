# Роли команды: Белбин × DISC

Каждая роль = один pi-сабагент. Карточка роли — это определение агента
для расширения `subagent` (пример: `examples/extensions/subagent`
в поставке pi): YAML-frontmatter (`name`, `description`, `model`) +
системный промпт. Раннер подставляет `{{model}}` из композиции `compositions/<слаг>.json`
(привязка «роль → модель» — решение владельца) и кладёт файлы
в изолированный pi-home прогона.

## Распределение

| Роль | Файл | Роль Белбина | DISC-профиль | Зона ответственности |
|---|---|---|---|---|
| Тимлид | `teamlead.md` | Координатор (Coordinator) | D высокий, I средний | оркестрация, продукт целиком |
| Аналитик-архитектор | `architect.md` | Мыслитель (Plant) | C высокий, D средний | анализ задания, архитектура, контракты |
| Фронтендер / UI-UX | `frontend.md` | Исследователь ресурсов (Resource Investigator) | I высокий, D средний | интерфейс, вёрстка, мобильность |
| Бэкенд-разработчик | `backend.md` | Реализатор (Implementer) | S высокий, C средний | Symfony: данные, подсчёт, LLM, почта |
| Ревьювер бэкенда | `reviewer.md` | Оценщик (Monitor Evaluator) | C высокий, I низкий | ревью кода и решений бэкенда |
| Девопс | `devops.md` | Мотиватор (Shaper) | D высокий, C средний | сборка, деплой, продакшен |
| Тестировщик | `tester.md` | Доводчик (Completer Finisher) | C высокий, S средний | проверки: поток, баллы, почта, прод |

DISC-профиль — варьируемый слой поведения (условие A серии): в промпте
роли он описан поведенческими паттернами через DISC-словарь. Для будущей
A/B-серии (условие B) те же роли описываются нейтрально, без DISC-словаря;
карточки B появятся отдельно, задание и состав не меняются.

## Правила для всех ролей

- Инструменты — дефолтные pi, ничего не отключается.
- Общая среда — рабочая директория прогона: код продукта, `team/journal.md`
  (журнал решений), `team/mailbox/<роль>/` (письма между ролями).
- Каждая роль по завершении задачи пишет отчёт в журнал и возвращает
  тимлиду структурированный итог (что сделано / файлы / заметки).
- Секреты из окружения не печатать в логах и отчётах.
- Выход за пределы рабочей директории запрещён, кроме деплоя девопса
  на согласованный путь продакшена.
Общие правила для агентов (среда, границы, данные) вынесены в
`../AGENTS.md` — раннер кладёт его в корень рабочей директории (`/work`),
pi подгружает в каждую сессию автоматически; раздел ниже — дублирующая
сводка для человека.
