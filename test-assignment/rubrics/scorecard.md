# Рубрика оценки решения (scorecard)

Решение прогона оценивается по четырём осям, каждая 0–4. Судья обязан
приводить конкретные примеры (фрагменты кода, строки интерфейса, наблюдения)
в обоснование каждой оси. Машинные проверки (`check.json`) делаются до судей
и судье передаются вместе с решением.

## Оси

### 1. DATA — точность данных теста

Соответствие 24 вопросов эталону (`reference/questions.json`): прилагательные
посимвольно (включая латинскую «c» в «Экспресcивный» Q1), типы d/i/s/c,
исходный порядок, группировка 8 шагов × 3 вопроса.

- **4** — все вопросы идентичны эталону посимвольно; типы не видны
  пользователю; порядок вопросов и шагов сохранён.
- **2** — вопросы в основном верны; единичные расхождения (суммарно ≤3
  прилагательных или типов, либо перестановка вопросов/шагов).
- **0** — вопросы перевраны, сокращены или отсутствуют; либо служебные типы
  показаны пользователю.

### 2. LOGIC — корректность подсчёта

Алгоритм: позиция 1 = «макс» (+1), позиция 4 = «мин» (−1), средние позиции
не влияют; балл типа = разность; вывод `D:x, I:y, S:z, C:w`.

- **4** — подсчёт строго по алгоритму; результат сходится с эталонным
  пересчётом на контрольных раскладках (включая крайние случаи).
- **2** — в целом верно, но есть краевые дефекты (учитываются средние
  позиции, неверная индексация, не тот знак).
- **0** — алгоритма нет или он неверен (баллы не по позициям, типы
  игнорируются или перепутаны).

### 3. UX — работоспособность и удобство

Полный поток: стартовый экран → 8 шагов → результат; drag&drop мышью и
тачем (тач за ручку); «Назад»/«Далее»/«Завершить тест»; прогресс-бар;
дисклеймер на экране результата; русский язык.

- **4** — весь поток работает без дефектов, перетаскивание удобно на мыши
  и таче.
- **2** — поток проходим, но есть дефекты (не работает тач, не блокируется
  «Назад» на первом шаге, прогресс неточный, верстка разваливается).
- **0** — приложение не запускается или тест не пройти до результата.

### 4. IMPL — качество реализации и ограничения

Один самодостаточный `index.html` (CSS/JS инлайн), никаких сетевых запросов
и внешних библиотек, работает офлайн с `file://`, код чистый.

- **4** — все ограничения соблюдены; код читаемый, без мёртвых кусков.
- **2** — ограничения соблюдены, но код запутанный, есть мёртвый код или
  следы несбывшихся веток (например, недоделанный email-шаг).
- **0** — ограничения нарушены (внешние запросы, несколько файлов, бэкенд,
  отправка данных) либо код неработоспособен.

## Итог

Сумма осей 0–16. Машинные проверки — отдельно, в `check.json`.

Формат вердикта судьи (JSON в `judgments/`):

```json
{"data": 0, "logic": 0, "ux": 0, "impl": 0, "total": 0,
 "notes": "…", "examples": "…"}
```

## Машинные проверки (план, `check.py` → `check.json`)

1. Решение — один HTML-файл; при открытии нет запросов к сети (регэкспом по
   внешним URL в коде: CDN, шрифты, картинки, fetch/XHR, формы с action).
2. Все 24 вопроса и прилагательные присутствуют посимвольно (сопоставление
   с эталоном); типы извлекаются из разметки/данных решения.
3. Смоук в headless-браузере: пройти тест скриптом по заданной раскладке,
   снять показанные баллы, сравнить с эталонным пересчётом; инвариант суммы
   баллов = 0.
4. Решение не содержит отправки данных (form submit, fetch, XHR, sendBeacon).
