# Рубрика оценки решения (scorecard)

Решение прогона оценивается по четырём осям, каждая 0–4. Судья обязан
приводить конкретные примеры (фрагменты кода, строки интерфейса, наблюдения)
в обоснование каждой оси. Машинные проверки (`check.json`) делаются до судей
и судье передаются вместе с решением.

## Оси

Важно: модель получает только задание со ссылкой на источник и работает
агентом (pi, инструменты по умолчанию) — материалы источника собирает сама
с живого сайта. Эталон (`questions.json`, `original.md`, снимок
`reference/source/`) ей недоступен; как модель изучала источник — видно
по трейсу сессии (`pi-session`). Качество самостоятельного изучения
и извлечения — часть переноса и оценивается осями ниже.

### 1. DATA — точность переноса данных

Соответствие 24 вопросов эталону (`reference/questions.json`): прилагательные
посимвольно, типы d/i/s/c, исходный порядок, группировка 8 шагов × 3 вопроса.
Исключение — известные опечатки оригинала (латинская «c» в «Экспресcивный» —
косяк Stratoplan): их исправление моделью — **плюс** (признак анализа данных),
а не отклонение; факт исправления фиксирует чекер (known_quirk_normalized).

- **4** — все вопросы идентичны эталону посимвольно; типы не видны
  пользователю; порядок вопросов и шагов сохранён.
- **2** — вопросы в основном верны; единичные расхождения (суммарно ≤3
  прилагательных или типов, либо перестановка вопросов/шагов).
- **0** — вопросы перевраны, сокращены или отсутствуют; либо служебные типы
  показаны пользователю.

### 2. LOGIC — точность переноса подсчёта

Алгоритм оригинала: позиция 1 = «макс» (+1), позиция 4 = «мин» (−1), средние
позиции не влияют; балл типа = разность; вывод `D:x, I:y, S:z, C:w`.

- **4** — подсчёт строго по алгоритму; результат сходится с эталонным
  пересчётом на контрольных раскладках (включая крайние случаи).
- **2** — в целом верно, но есть краевые дефекты (учитываются средние
  позиции, неверная индексация, не тот знак).
- **0** — алгоритма нет или он неверен (баллы не по позициям, типы
  игнорируются или перепутаны).

### 3. UX — точность переноса потока и работоспособность

Полный поток оригинала: стартовый экран → 8 шагов → результат; подписи
«Я наиболее»/«Я наименее», «Назад»/«Далее»/«Завершить тест», табы шагов,
прогресс-бар, дисклеймер на экране результата; drag&drop мышью и тачем
(тач за ручку); русский язык.

- **4** — весь поток работает без дефектов, перетаскивание удобно на мыши
  и таче.
- **2** — поток проходим, но есть дефекты (не работает тач, не блокируется
  «Назад» на первом шаге, прогресс неточный, верстка разваливается).
- **0** — приложение не запускается или тест не пройти до результата.

### 4. IMPL — качество реализации и адаптации под ограничения

Оценивается сам `index.html`: CSS/JS инлайн, никаких сетевых запросов
и внешних библиотек (SortableJS заменён своей реализацией drag&drop),
работает офлайн с `file://`; обязательные адаптации выполнены: email-шаг
и редирект убраны (результат в том же приложении), токен/шифрование убраны,
маркетинговые блоки не перенесены; код чистый.

Рабочие файлы агента в run-каталоге (скачанные исходники источника,
собственные тест-скрипты, черновики) — **НЕ недостаток**: это след
исследования и материал под возможные доработки, удалять и штрафовать
за них нельзя. Решение — только `index.html`.

- **4** — все ограничения соблюдены, адаптации выполнены точно; код
  читаемый, без мёртвых кусков.
- **2** — ограничения соблюдены не полностью или адаптации с огрехами
  (следы убранного email-шага, остатки токен-логики); код запутанный.
- **0** — ограничения нарушены (внешние запросы/CDN в `index.html`,
  бэкенд, отправка данных, email-шаг) либо код неработоспособен.
  Рабочие файлы агента рядом с решением — не штрафуются.

## Итог

Сумма осей 0–16. Машинные проверки — отдельно, в `check.json`.

Формат вердикта судьи (JSON в `judgments/`):

```json
{"data": 0, "logic": 0, "ux": 0, "impl": 0, "total": 0,
 "notes": "…", "examples": "…"}
```

## Машинные проверки (план, `check.py` → `check.json`)

1. Решение — один HTML-файл; при открытии нет запросов к сети (регэкспом по
   внешним URL в коде: CDN, шрифты, картинки, fetch/XHR, формы с action).
2. Все 24 вопроса и прилагательные присутствуют посимвольно (сопоставление
   с эталоном); типы извлекаются из разметки/данных решения.
3. Смоук в headless-браузере: пройти тест скриптом по заданной раскладке,
   снять показанные баллы, сравнить с эталонным пересчётом; инвариант суммы
   баллов = 0.
4. Решение не содержит отправки данных (form submit, fetch, XHR, sendBeacon).
